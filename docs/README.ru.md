**Подключаемые модули возможностей для coding‑агентов** — добавляйте, обновляйте и расширяйте skills и rules из Git для Cursor, Claude Code, Codex, GitHub Copilot и других агентов.

---

## Цели

Agent Bay — инструмент с открытым исходным кодом (в планировании), решающий проблемы **разрозненной конфигурации агентов, слабого версионирования и потери настроек при смене машины** для команд и отдельных разработчиков с несколькими coding‑агентами.

Мы рассматриваем **Agent Skills** (открытый формат [`SKILL.md`](https://agentskills.io)) и **правила агентов** (например `.cursor/rules`, `AGENTS.md`) как **подключаемые модули**:

1. **Вертикальное обновление** — получать или обновлять пакеты возможностей из Git, чтобы агенты быстро получали новые workflow, стандарты и предметные знания.
2. **Горизонтальное распространение** — отображать те же модули в нативные пути каждого продукта (Cursor, Claude Code, Codex, Copilot, …) без ручного копирования dotfiles.
3. **Аудируемая совместная работа** — Git как источник истины; установленные копии — управляемые артефакты с инкрементальной синхронизацией и очисткой.
4. **Skills и rules** — **Skills** по запросу и постоянные или path‑scoped **Rules** на отдельных рельсах, в духе отраслевого сдвига к skills с сохранением `alwaysApply` / globs где нужно.

Agent Bay **не** веб‑краулер и **не заменяет** публичные реестры skills (например [skills.sh](https://skills.sh) / `npx skills`). Фокус — **ваши Git‑репозитории** как authority для **установки модулей и развёртывания по нескольким каналам агентов**.

---

## Метафора: bay (отсек)

Как **слоты расширения (bay)** на роботе: в каждом bay — один модуль возможностей (skill‑пак, фрагмент rule или catalog‑bundle). Замена, добавление и обновление модулей должны быть **быстрыми** и **повторяемыми**.

---

## Статус

**Ранняя стадия** — репозиторий задаёт цели, соглашения и реализацию; API и CLI пока нестабильны.

Issue и PR приветствуются по форматам модулей и семантике синхронизации.
